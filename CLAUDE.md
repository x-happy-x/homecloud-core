# homecloud-core — распознавание и каталог HomeCloud

Бэкенд домашней фототеки: обходит диски, прогоняет снимки и ролики через
локальные модели, складывает результат в SQLite и отдаёт по HTTP. Ничего
никуда не загружается — всё считается на этой машине.

Интерфейс живёт **в другом репозитории** (`F:\services\homecloud`) и на другой
машине. Здесь — только API и медиа.

## Почему так разнесено

Видеокарта, ONNX Runtime и InsightFace привязаны к Windows, а интерфейс должен
быть доступен, когда эту машину трогать не хочется. Поэтому:

| | где | что |
|---|---|---|
| бэкенд | Windows, порт **18311** | этот репозиторий: модели, каталог, оригиналы |
| интерфейс | VM `family-apps` 192.168.99.20, порт **4180** | `homecloud`: раздача статики и обратный прокси, в Docker Compose рядом с bigfam, account и LLDAP |

Бэкенд поднимается только через `backend.ps1` — иначе идентификатор устройства
перестанет совпадать с записью в реестре устройств на VM. После правок
`web_server.py` его надо перезапускать руками.

## Каталог

SQLite-файл `catalog.sqlite` внутри папки каталога (по умолчанию
`trash-clean-catalog`). Ключ почти везде — **путь к файлу**; он не меняется,
даже когда файл физически переезжает (скрытый альбом помнит новое место
отдельно, в `hidden_photos.stored`).

Таблицы по темам:

- **опись:** `photos` (путь, размер, mtime, `kind` фото/видео, `duration`,
  `status`), `photo_dirs`, `scan_roots`, `scan_exclusions`, `scan_runs`
- **лица:** `faces` (рамка, эмбеддинг, миниатюра, `frame_time`,
  `track_start`/`track_stop` — у фотографий NULL), `face_clusters`,
  `face_people`, `people`, `face_exclusions`, `face_authenticity`,
  `group_avatars`, `label_history`
- **анализ:** `photo_analysis` (тип, качество, OCR), `photo_embeddings`
  (визуальный индекс), `photo_adult_analysis`, `photo_hashes` (sha1 + dHash)
- **видео и звук:** `video_speech`, `video_speech_segments`,
  `video_diarization`, `video_speakers`, `video_speaker_turns`,
  `video_speaker_faces`, `voice_prints`
- **подборки:** `albums`, `album_photos`, `people_albums`,
  `people_album_members`, `hidden_photos`
- **обучение:** `router_models`, `router_predictions`, `router_reviews`,
  `router_training_labels`, `router_batches`, `router_batch_items`
- **настройки:** `settings`

Ключ группы в разделе «Люди» — строка одного из четырёх видов:
`person:<id>` (названный человек), `auto:<label>` (автоматическая гроздь),
`noise`, `excluded`. Ключи `auto:` стабильны между запусками.

## Модели

Все локальные, кроме необязательного LM Studio (тоже свой, соседний).

| Этап | Модель | Окружение |
|---|---|---|
| Лица: детекция и эмбеддинг | InsightFace `buffalo_l` (SCRFD + ArcFace), ONNX Runtime на CUDA | `.venv` |
| Группировка лиц | `sklearn.cluster.HDBSCAN`, `min_cluster_size=8`, метрика euclidean | `.venv` |
| Визуальный индекс | `google/siglip2-base-patch16-224` (по умолчанию), либо `siglip2-base-patch16-256`, либо `jinaai/jina-clip-v2` — выбирается в настройках | `work/vision-venv` |
| Рейтинг 18+ | `SmilingWolf/wd-eva02-large-tagger-v3` + NudeNet (`NudeNet-320n-exif`) для областей | `work/vision-venv` |
| Описания | `Qwen/Qwen3-VL-2B-Instruct` локально либо LM Studio по адресу из настроек | `work/vision-venv` |
| Рисованные лица | `deepghs/anime_real_cls`, вариант `mobilenetv3_v1.4_dist` (пакет `dghs-imgutils`) | `work/imgutils-venv` |
| OCR | PaddleOCR, `lang='ru'`, **на процессоре** | `C:\cv-ocr` |
| Речь | Whisper `large-v3` через faster-whisper, `float16` на CUDA; звук достаёт PyAV из комплекта | `work/audio-venv` |
| Разделение голосов | `pyannote/speaker-diarization-community-1` | `work/audio-venv` |
| Дубликаты | без моделей: sha1 для точных копий, dHash для похожих | `.venv` |

`device_job.py` сам выбирает интерпретатор под этап — правки путей искать
там (строки со `*_python`).

**Окружений пять, и это не случайность.** `dghs-imgutils` тянет numpy<2 и
`opencv-contrib-python`, которые ломают `cv2` в любом окружении, где уже стоит
`opencv-python-headless` — конфликт на уровне файлов, не версий. Никогда не
ставить его в общее окружение. PaddleOCR живёт отдельно по той же причине.

Рейтинг 18+ ставится **по согласию двух моделей**: NudeNet даёт области,
WD-tagger — рейтинг и теги. Текст и интерфейсы отсекаются по тегам,
`sensitive` не замыливается. У роликов берётся несколько кадров по всей длине
и остаётся худший: одного кадра из начала мало.

## Как устроено сканирование

Два шага, и это важно:

1. **Опись** (`catalog_index.py`, задание с `features={"inventory":true}`) —
   обход выбранных корней, дерево найденного с состояниями файлов, применение
   исключений. Пишет в `photos` **порциями по ходу обхода**, а не одной
   транзакцией в конце: остановка на середине большого прогона больше не
   теряет всё найденное.
2. **Этапы обработки** — идут только по тому, что осталось после исключений.

Каждый этап **инкрементальный**: помнит размер и mtime файла и пропускает уже
посчитанное. У всех скриптов и у `device_job.py` есть `--force`.

Исключённые файлы получают `photos.status='excluded'` — их не видит ни один
этап. Файл, не обойдённый на этом проходе, помечается `missing` только если он
не подпадает под `pathrules`, встроенные исключения (`$RECYCLE.BIN` и прочее)
и `scan_exclusions` — иначе `excluded`.

Порядок этапов и их зависимости описаны в `device_job.py`; визуальный индекс
строится не только ради поиска, но и как вход для OCR и описаний.

Задание публикует в `device-job-progress.json` план этапов (`plan`, порядок
`planned_phases()` обязан совпадать с `run()`), историю этапов
(`phase_history`: начало, момент загрузки модели — первый обработанный файл,
конец, счётчики) и замеры прошлых запусков (`timings`, файл
`device-timings.json` рядом с каталогом: секунды загрузки и на файл по ключу
«этап:вид»). Из них интерфейс считает, сколько осталось всему заданию.

## Точки входа

```powershell
.\backend.ps1 -DeviceId pc-x -DeviceName PC-X   # API на 18311
.\setup.ps1                                      # окружения и модели
.\scan-photos.ps1                                # разовый прогон этапов
```

`web_server.py` — единственный HTTP-слой: `/api/*` (состояние каталога, люди,
альбомы, сканирование, дубликаты, обучение, речь) и `/media/*` (`photo` с
`size` и `blur`, `video` с Range, `face-crop/<id>`, `original`). Изменяющие
запросы проверяют заголовок **`X-Local-Token`** — не `Authorization: Bearer`,
тот только для GET. Ручные проверки POST должны слать оба.

Кто смотрит, бэкенд узнаёт из `X-HomeCloud-User` / `X-HomeCloud-Role`, которые
ставит Node-сервер на VM; браузерные значения там затираются. Сам вход —
не здесь: им занимается сервис `account` поверх LLDAP.

## Правила, которые дорого нарушить

- **Деструктивный `DELETE` должен идти рядом с `INSERT` новых данных**, а не
  раньше. Пересборка групп раньше сносила `face_clusters` первым шагом, и
  прерывание оставляло каталог вообще без групп.
- **Длинные операции — отдельный поток на своём соединении к SQLite.** Один
  объект `Connection` из двух потоков даёт дичь вместо ошибки. Образец —
  `DuplicateService` и `ReclusterController` в `web_server.py`.
- **Плотная выборка кадров видео — только последовательным чтением с `grab()`.**
  Перемотка `CAP_PROP_POS_FRAMES` на каждый кадр медленнее в 3–14 раз.
- **`os.replace()` файла прогресса оборачивать в несколько попыток** — редкий
  `PermissionError: WinError 5` от параллельного чтения статуса ронял задание.
- **Голосование «какое лицо говорит» вести по группам лиц, а не по `face_id`**:
  человек за ролик выходит из кадра и возвращается, у каждого появления свой
  трек, а голос один.
- **Скрипты `.ps1` держать в UTF-8 с BOM** — иначе Windows PowerShell 5.1
  ломает кириллицу и падает на разборе.
- Каталог принадлежит учётке `CodexSandboxOffline`, поэтому он добавлен в
  `git config --global safe.directory`.
